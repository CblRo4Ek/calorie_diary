# Исследование датасетов и итоговое решение

## Принятое решение для бейзлайна

Использовать **FPB + MyFoodRepo v2.1** в едином формате YOLO detection. Оба источника содержат разметку отдельных объектов на фотографии.

- FPB — основа: 138 исходных классов и их ID 0–137, авторские рамки и train/val. Масса исключается при чтении шестого поля TXT.
- MyFoodRepo v2.1 — дополнение: 323 класса, реальные пищевые дневники, несколько объектов на фото, COCO-сегментация. Рамки восстанавливаются по полигонам.
- Food-101 исключён из обучения и доступен только как отдельный сэмпл фотографий без разметки для просмотра предсказаний итоговой модели.

## Почему отказались от Food-101 в обучении

**Food-101 был протестирован:** выполнены загрузка, пробное объединение с FPB и просмотр изображений. Принято решение не использовать его для обучения детектора: в датасете есть только класс всего изображения, нет разметки отдельных объектов, а на многих фотографиях присутствуют несколько блюд. Экспериментальная рамка на весь кадр не описывает реальные границы и состав объектов.

Food-101 можно использовать для проверки работы итоговой модели на разнообразных веб-фотографиях. В текущем ноутбуке сохраняются только фотографии и manifest без классов, bbox и labels. Это **качественная проверка предсказаний**, а не размеченная выборка для расчёта mAP. Для количественной оценки нужна собственная объектная разметка. Старые результаты эксперимента с Food-101 не являются обучающими сборками нового пайплайна.

## Сравнение основных источников

| Критерий | Food-101 | FPB | MyFoodRepo v2.1 |
| --- | --- | --- | --- |
| Опубликованный объём | 101 000 фото, 101 класс | 14 083 фото, 138 классов | Train: 54 392 фото / 100 256 аннотаций; valid: 946 фото / 1 708 аннотаций; 323 класса |
| Разметка | Класс всего изображения | Класс и рамка объекта; поле массы | Класс и сегментация каждого объекта |
| Детекция | Нет объектной разметки | Авторские рамки | Рамки из полигонов |
| Съёмка | Разнообразные веб-фото, возможны несколько блюд | Контролируемая съёмка, несколько ракурсов | Реальные пищевые дневники |
| Роль в проекте | Отдельные фото без разметки для проверки предсказаний | Основа бейзлайна | Второй обучающий источник |
| Импорт | Выбранные фото из оригинального test через HF Viewer | YOLO TXT, первые 5 полей | COCO, разреженные category ID и полигоны |
| Ограничения | Нет bbox, права исходных фотографий | CC BY-NC 4.0, лабораторная съёмка | CC BY 4.0; стороннее зеркало и проблемы аннотаций требуют проверки |

В закреплённой revision FPB фактически обнаружено **14 076 изображений**: 9 518 train, 2 362 val, 2 196 test. Это отличается от сводной карточки; используются реальные файлы, открытые тестовые метки не предполагаются.

## MyFoodRepo: проверка версии и исправление разметки

Теперь в ноутбуке 02 параметр `MYFOODREPO_SOURCE = "archives"` выбирает локальные `data/public_training_set_release_2.1.tar` и `data/public_validation_set_release_2.1.tar`. Режим `"download"` загружает train с закреплённого зеркала, а valid берёт из локального архива: в проверенном зеркале valid отсутствует. Версия v2.0 не подставляется. Проверяются объёмы, уникальность ID и совпадение словарей train/valid; в локальных архивах обнаружены 54 392/946 изображений, 100 256/1 708 аннотаций и 323 одинаковые категории.

Поля bbox не всегда соответствуют COCO xywh и полигонам. При импорте границы вычисляются по минимумам и максимумам координат полигонов и нормализуются по размеру изображения. В train в 175 аннотациях найдены дополнительные вырожденные компоненты из одной-двух точек; они игнорируются при наличии валидных полигонов. Удаляются 2 613 точных повторов объекта того же класса на одном изображении. До удаления дубликатов фотографий в train остаётся **97 643 объекта**. Аудит изменений для архивов хранится в `data/metadata/myfoodrepo_v2_1_archives/{train,val}/import_audit.json`, для train с зеркала — в `data/metadata/myfoodrepo_v2_1/import_audit.json`.

Авторские разбиения MyFoodRepo сохраняются: train остаётся train, valid из 946 фото становится YOLO-разделом `val`. Дополнительное случайное разбиение train в ноутбуке 02 больше не выполняется. В `preview` используется небольшой сэмпл каждого разбиения. Распакованные изображения сохраняются в `data/raw/myfoodrepo_v2_1_archives/{train,val}/images/`, JSON и отметки завершения — в `data/metadata/`. Повторный запуск использует распаковку и готовую сборку из кеша; при смене источника требуется `OVERWRITE = True`. Общая проверка пиксельных дубликатов между выборками сохраняется.
