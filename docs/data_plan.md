# Краткий план подготовки данных

1. Выполнить `uv sync --locked`; открыть `uv run --locked jupyter lab` или выбрать `.venv` как kernel в VS Code. Зависимости описаны в `pyproject.toml` и зафиксированы в `uv.lock`.
2. Выполнить `notebooks/01_review_class_synonyms.ipynb`: посмотреть пары, подтвердить merge/keep_separate, сохранить CSV решений в `data/review/`.
3. Выполнить `notebooks/02_prepare_fpb_food101.ipynb` сначала в `MODE="preview"`: проверить общий словарь, таблицу источников и рисунки с сохранёнными рамками.
4. Переключить второй ноутбук в `MODE="full"`; получить полный экспорт в `data/processed/fpb_food101/`. Здесь хранится одна текущая сборка; новый успешный запуск заменяет её целиком. Каталоги, индексы и список примеров сохраняются в `data/metadata/` для ускорения повторного запуска. Рисунки выводятся только в ноутбуке, папка `reports/` не создаётся. Уникальные классы Food-101 сохраняются, масса исключается.
5. Просмотреть `class_mapping.csv`, `excluded_records.json` (если есть исключённые записи), распределение по классам и источникам в ноутбуке. Дополнительно проверить похожие ракурсы FPB, не выявляемые точным хешем.
6. Обучить FPB-only и FPB+Food-101 с одинаковыми настройками; сравнить локализацию на FPB и распознавание на независимых фото из Telegram. Пользу уникальных классов и условных рамок проверить экспериментом.
7. По ошибкам решить, нужны ли MyFoodRepo в продвинутой версии.
