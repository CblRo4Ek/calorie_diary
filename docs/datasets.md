# Исследование датасетов и итоговое решение

## Принятое решение для бейзлайна

Использовать **FPB + Food-101**, приведённые к обычному YOLO detection. Добавление MyFoodRepo отложено до продвинутой версии и зависит от результатов проверки на пользовательских фото.

- FPB — основа: сохранить классы и исходные рамки. Массу не использовать. При чтении исходного TXT шестой столбец отбрасывается; очищенные исходные и итоговые TXT содержат только пять полей.
- Food-101 — дополнение: рамка по решению проекта занимает весь кадр, `0.5 0.5 1 1`. Уникальные классы остаются в словаре и включаются в полную загрузку.
- Восемь одинаковых названий объединяются с FPB по умолчанию. Синонимы объединяются только после визуальной проверки и явной отметки в таблице решений.
- Канонические имена и ID берутся из FPB; уникальные классы Food-101 добавляются в конец. Названия на русском следует хранить отдельным справочником интерфейса.

Рамка Food-101 — **условная разметка всего изображения**, а не истинная граница еды. Дополнительные категории могут помочь обобщению, но это гипотеза. Сравнивать FPB-only и FPB+Food-101 нужно на одной целевой выборке; качество локализации оценивать отдельно на FPB с настоящими рамками.

## Сравнение основных источников

| Критерий | Food-101 | FPB | MyFoodRepo v2.1 |

| Детекция | В бейзлайне добавляем полную рамку | Готовые рамки | Готовая разметка объектов |
| Съёмка | Веб-фото блюд | Контролируемая съёмка, несколько ракурсов | Реальные пищевые дневники пользователей |
| Назначение | Расширение классификационных категорий | Основа принятого бейзлайна | Возможное расширение под бытовые фотографии |
| Импорт | Parquet с изображением и label | Авторские TXT; оставить первые 5 полей | COCO JSON |

Источники: [Food-101 / ETH](https://data.vision.ee.ethz.ch/cvl/datasets_extra/food-101/), [метаданные Food-101](https://huggingface.co/datasets/ethz/food101), [FPB](https://huggingface.co/datasets/issai/Food_Portion_Benchmark), [формат FPB](https://github.com/IS2AI/Multitask-Food-Portion-Estimation), [MyFoodRepo v2.1](https://www.aicrowd.com/challenges/food-recognition-benchmark-2022), [условия MyFoodRepo](https://www.aicrowd.com/challenges/food-recognition-benchmark-2022/challenge_rules).

FPB включает борщ, блины, гречку, оливье, окрошку, сырники и другие знакомые блюда: [опубликованный data.yaml](https://huggingface.co/datasets/issai/Food_Portion_Benchmark/blob/main/FPB_Dataset/RGB/data.yaml). Это аргумент в пользу проверки FPB первым, а не доказательство превосходства по точности.

При индексации текущей FPB revision обнаружено **14 076 файлов изображений**: 9 518 train, 2 362 val, 2 196 test. Это отличается от сводной карточки; загрузчик использует реальные файлы и проверяет наличие меток, не подставляя заявленное число. Тестовые метки FPB в описании скрыты.

## Пересечение классов и решения о синонимах

Точно совпадают названия: `beet_salad`, `caesar_salad`, `cheesecake`, `french_fries`, `greek_salad`, `pizza`, `ramen`, `tiramisu`.

| FPB | Food-101 | Начальное решение |
| --- | --- | --- |
| icecream | ice_cream | Раздельно до визуального подтверждения |
| cupcake | cup_cakes | Раздельно до визуального подтверждения |
| pahlava | baklava | Раздельно до визуального подтверждения |
| burger | hamburger | Проверить ширину категории |
| bliny | pancakes | Близкие блюда; автоматически не объединять |
| salmon | grilled_salmon | Общая категория и конкретное приготовление |
| fried_dumplings | dumplings | Подтип и общая категория |
| samsa | samosa | Разные блюда с созвучными названиями |

После объединения только восьми точных имён в словаре **231 класс**: `138 + 101 - 8`. Если подтвердить ещё три вероятных синонима — **228 классов**. Это число классов словаря, а не утверждение о полном покрытии небольшого preview.

Таблица решений сохраняется в `data/review/class_synonym_decisions.csv`. Только `decision=merge` вместе с `reviewed=True` разрешают переименование. При `keep_separate` уникальное имя Food-101 сохраняется. Если вручную отклонено совпадение одинаковых имён, Food-101 получает префикс `food101__`.

FoodInsSeg использует изображения FoodSeg103: эти наборы нельзя считать независимыми источниками фотографий. MyFoodRepo размечает отдельные продукты/блюда, но не гарантирует выделение всех ингредиентов смешанного блюда. Для ингредиентов предназначены FoodInsSeg/FoodSeg103/CMIngre.

Сегментационные маски читаются как ID классов, масштабируются nearest-neighbor. Для COCO сохраняется исходная связь image/category/annotation; для VOC читаются все `object`, а не только первый. Полигоны можно превратить в рамки через min/max координат. У неизвестных архивов сначала проверяется реальная схема поставки.

## Формат результата и защита от ошибок

Строка итогового TXT:

```text
class_id x_center y_center width height
```

Все координаты нормализованы, ID последовательны и одинаковы во всех splits. Рамки FPB сохраняются, Food-101 получает `class_id 0.5 0.5 1 1`. Исходные изображения не переименовываются на месте: формируется отдельный экспорт с префиксами источников и устойчивыми идентификаторами.

- Оригинальный Food-101 test (на HF назван `validation`) остаётся test. Validation выделяется из исходного train по классам с фиксированным seed.
- FPB train/val сохраняются. Изображения test без доступных меток хранятся отдельно как `fpb_test_unlabeled`, не выдаются за фон и не попадают в размеченные списки.
- Точные пиксельные дубликаты удаляются с приоритетом holdout; конфликтующая разметка одинакового фото исключается с объяснением. Варианты исходного имени FPB не пересекают splits.
- Физические ID тарелок/порций в текущей поставке не установлены. Проверка имён и точных пикселей не доказывает отсутствие похожих ракурсов одной порции. dHash сохраняется для дополнительного аудита.
- Проверяются открываемость изображений, ID и рамки, наличие меток, равенство сохранённого TXT и manifest. Пустая метка допустима только как существующий файл, а не замена отсутствующего.
- `manifest.jsonl` хранит источник, source ID, split, происхождение рамки, контрольные суммы; масса исключена. `class_mapping.csv` объясняет переименование.
- Для локализации создаётся отдельный `fpb_eval.yaml`. Метрики на полном кадре Food-101 нужно интерпретировать отдельно от реальных bbox FPB.

## Где находятся данные и ноутбуки

```text
data/
  metadata/                 # каталоги, индексы источников и список примеров для повторного запуска
  raw/fpb/<revision>/       # фото и очищенные 5-полевые TXT
  raw/food101/<revision>/   # фото Food-101
  cache/                    # Parquet и технические кеши
  review/                   # решения о синонимах
  processed/fpb_food101/    # единственная текущая сборка: изображения, labels, YAML, manifest, mapping
```

Каталоги, индексы источников и список примеров кешируются в `metadata/` и переиспользуются между запусками и после перезапуска ядра. Визуальные сравнения выводятся в ноутбуках без отдельных файлов в `reports/`. Версии источников хранятся в `metadata/sources.lock.json`, решения о синонимах — в `review/class_synonym_decisions.csv`; в `processed/` они не дублируются. `excluded_records.json` создаётся только при наличии исключений. Статистика сборки выводится в ноутбуке, без `build_complete.json`. При повторной подготовке новая проверенная сборка заменяет предыдущую целиком, независимо от режима preview/full.

1. [01_review_class_synonyms.ipynb](../notebooks/01_review_class_synonyms.ipynb) — просмотр пар, решения о переименовании.
2. [02_prepare_fpb_food101.ipynb](../notebooks/02_prepare_fpb_food101.ipynb) — загрузка, очистка, объединение и проверка сохранённых рамок.
